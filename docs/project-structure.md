## Package layers

```
splashpy/
├── dictionary/    protocol constants: services, tasks, operations, definitions
├── protocol/      wire layer
│   ├── xmlsafe    safe XML parsing (the only parser entry point)
│   ├── codec      Splash XML encoding / decoding
│   ├── cipher     legacy AES-256-CBC encryption
│   ├── message    pack / unpack = XML + encryption
│   └── soap       minimal SOAP 1.1 envelope
├── config/        SplashConfig (immutable) and providers (Static, Env, Json)
├── core/          RequestContext, Logger, ClientInfo, server information
├── server/        incoming requests
│   ├── handler    services: Ping, Connect, and task services
│   ├── runner     executes the tasks list of a request
│   └── routers/   Admin, Objects, Widgets, Files
├── transport/     HTTP transport for outgoing calls (injectable)
├── client.py      SplashClient: serves Splash, calls Splash
├── adapters/      HTTP gateways (WSGI)
├── cli.py         `splashpy version`, `splashpy serve`
├── fields/        field types, fluent FieldsFactory, values helpers (lists, ids, prices, files...)
├── objects/       BaseObject, FieldsGroup, pipeline resolver, handler, locks, commits
├── widgets/       BaseWidget, per-render output, BlocksFactory
├── extensions/    Extension hooks, per-client registry (explicit + allowlisted entry points)
├── faker/         demo connector (short, simple, list, primary, image, file + widgets), dev & tests only
├── contracts/     (milestone 3) field templates and scopes
└── testing/       (milestone 3) conformance test suite for connectors
```

### Dependency rule

Layers only depend on layers below them:

```
dictionary ◄── protocol ◄── config / core ◄── fields ◄── objects / widgets / extensions
                                                     ◄── server / transport ◄── client ◄── adapters / cli
```

- `protocol` knows nothing about clients, configuration or HTTP;
- `server` knows nothing about HTTP;
- `client` composes server, protocol and transport;
- `adapters` and `cli` only use the public client API.

### No hardcoded protocol strings

Every service name, task name, operation or definition lives in `splashpy.dictionary`
(`SplServices`, `SplAdminMethods`, `SplObjectMethods`, `SplFilesMethods`, `SplWidgetsMethods`,
`SplOperations`, `SplDefinition`), mirroring Php-Core dictionaries.

## Request flow

### Serving Splash (incoming)

```
HTTP body ──► SplashClient.handle_request()
                 │  new RequestContext: config, logger, request host / path / user agent
                 ▼
              soap.parse_request()                   invalid ──► Client fault (HTTP 500)
                 ▼
              ServiceHandler.handle()
                 │  Ping ──► unsecured {result}
                 │  wrong webservice id ──► empty response
                 │  MessageCodec.unpack() fails ──► empty response
                 ▼
              TaskRunner.run() ──► router of the service, task by task
                 ▼
              outputs + result + request logs ──► MessageCodec.pack()
                 ▼
              soap.build_response()                  crash anywhere ──► Server fault
```

### Calling Splash (outgoing)

```
client.ping() / connect() / commit() / call()
   ──► {server, service, debug, verbose, tasks, taskscount}
   ──► MessageCodec.pack() ──► soap.build_request() ──► Transport.post()
   ──► soap.parse_response() ──► MessageCodec.unpack() ──► logs merged
```

Outgoing calls never raise: failures are logged and the call returns `False` / `None`.

## State & concurrency

- `SplashClient` is built once and holds only immutable settings and stateless services.
- Each request (incoming or outgoing) creates a `RequestContext` holding its logger, debug flags
  and request information. Nothing is stored on shared objects.
- One client can serve concurrent requests from several threads; several clients (databases,
  tenants) can live in the same process. Both are covered by tests.

## Tests organisation

| Folder                 | Scope                                                                 |
|------------------------|-----------------------------------------------------------------------|
| `tests/unit/protocol`  | golden tests against Php-Core (wire layer, fields definitions), codec, cipher, SOAP |
| `tests/unit`           | configuration, logger, information, transport, small helpers          |
| `tests/integration`    | serving requests, objects pipeline & CRUD, routers, extensions, faker, outgoing calls, isolation, WSGI, CLI |
| Docker E2E stack       | Splash Toolkit 3.0 suites against the faker, on every Python version  |
